VibeGuard v2 · Rust CLI · MIT licensed

Native hooks for Claude Code, Codex and Grok.

VibeGuard rejects selected destructive Bash commands and keeps source files from growing past 800 lines. Optional Git ancestry checks and installation diagnostics come in the same Rust executable.

What the current runtime checks

  • Native Bash hooks: reject selected bulk Git restore, forced Git clean, and recursive forced deletion spellings. Results record only the latest observed outcome.
  • 800-line limit, before an edit (Claude Code): refuses a Write, Edit or MultiEdit that would leave a source file above 800 lines and longer than before. Existing large files may shrink but not grow.
  • 800-line limit, after a Bash call (Claude Code, Codex): tells the Agent which source files grew past the limit. Nothing is blocked.
  • 800-line limit, at commit (optional, per repository): install git-size adds a pre-commit hook that refuses the growth however the file was written, from any tool.
  • Optional Git pre-push hook: checks commit ancestry, rejects remote ref deletion and replacement of existing tags, and requires fast-forward branch updates.
  • Installation diagnostics: report hook registration, executable mode bits, local hook settings, and the last observation.

The Bash classifier is not a complete shell parser or sandbox. Alternate commands and disabled or untrusted hooks can bypass it; Git hooks are also bypassable. A reported zero exit code does not prove that tests ran or that the current tree is verified. The host owns permissions and the agent loop.

Read the runtime contract for the exact enforcement and evidence boundaries.

Install

One command downloads the latest release for your OS and CPU, verifies its checksum, and runs install. Preview first with --dry-run:

curl -fsSL https://raw.githubusercontent.com/majiayu000/vibeguard/main/install.sh | bash -s -- claude --dry-run
curl -fsSL https://raw.githubusercontent.com/majiayu000/vibeguard/main/install.sh | bash -s -- claude

Replace claude with codex or grok. To add the commit-time line limit to a repository:

~/.vibeguard/bin/vibeguard-runtime install git-size --repo /absolute/path/to/repository

Or download your OS and CPU archive from GitHub Releases, extract it, and open a terminal in that directory. macOS, Linux, and WSL are supported; choose a Linux archive for WSL. This path does not require a Rust toolchain.

./vibeguard-runtime install codex
# Or select Claude Code:
./vibeguard-runtime install claude
# Or select Grok:
./vibeguard-runtime install grok

Restart the selected host and review its native hook trust settings.

~/.vibeguard/bin/vibeguard-runtime status codex

Use claude or grok instead of codex for those hosts. Native Windows installation is experimental and covers Claude Code with Git Bash; see the Windows instructions.

For source builds, optional Git push protection, v1 upgrade instructions, or uninstall, follow the current README. V2 removes the rule library, the earlier static scanners, learning metrics, workflow routing, and Stop/test-keyword gates.

Hooks are installed. Why is protection still uncertain?

~/.vibeguard/bin/vibeguard-runtime status codex

Use status claude or status grok for those hosts. An incomplete result points to registration, executable mode bits, or local hook settings. Prompt text is not an installation-health requirement. Check the reported paths and the status contract. Even a complete result cannot establish host trust or reload state; restart the host and review its native hook settings. The last observation is a diagnostic, not proof that the current code passed tests.

Does VibeGuard block every risky action?

No. The runtime enforces selected Bash spellings, the line limit, and the optional Git pre-push policy; other tools and arbitrary shell programs are outside the Bash checks. Keep host permissions and repository protection in place. See what is checked and the protocol boundaries.

Why did a file still grow past 800 lines?

The edit check only sees Claude Code's Write, Edit and MultiEdit. A script run from the shell goes around it, and gets a notice after the fact instead. Only the commit hook stops every way of writing a file, and it has to be installed per repository; --no-verify skips it, and rebases and fast-forward merges don't run it. See the 800-line limit.

Why do older instructions mention different commands?

V2 removed the earlier scanners, proxy, and workflow systems. Use the README bundled with your exact release archive. For an existing v1 installation, follow the version-specific uninstall sequence before installing v2; v2 inventories legacy files but leaves them in place.

For a reproducible installation or command problem, open a GitHub issue with the release version, platform, command, and redacted status output. Use the security policy for vulnerability reports.
