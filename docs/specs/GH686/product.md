# Product Spec — prompt 注入规则的 with/without 配对评测（副作用门）

## Linked Issue

GH-686

complexity: large

## 用户问题

行为评测门（`eval/behavior/`，#684 扩展）只覆盖 **hook 强制**的规则：它能确定性地
同时检出漏拦和误拦。**prompt 注入规则**（compact L1-L7 表 + `rules/claude-rules/`
下的原生规则文件）没有等价的副作用门。

本门只覆盖**带 `<ID>` 的原生规则定义**：入口是候选规则 ID，在场断言依赖
`## <ID>:` 定义。compact L1-L7 层级项没有 ID、也没有这样的定义，不在本门范围内。
若候选语义仍被匿名 compact 项保留（当前映射为 U-04→L5、U-17/U-23/U-29→L3、
U-24→L2、SEC-02→L7），with/without 就不是有效对照，必须在调用模型前明确拒绝该候选。

一条 prompt 规则可以在它自己的目标场景上"正确"，同时**在无关任务上劣化 agent
行为**——约束衰减 / 注意力挤占（U-32 引用的研究）。今天没有任何东西在规则上线前
度量这一点。VibeGuard 自己的 U-32 规定活跃约束 ≤15，但没有实验数据支撑任何一条
新规则是否值得占用这个预算。

现状（本会话核实）：

- `eval/run_eval.py:215` 已经把规则来源参数化，并对规则文本取 `rule_digest`。
- 但规则文本有**两个**注入来源：`--rules-dir` 的规则树，以及无条件拼上的
  `--core-rules-file`（默认 `claude-md/vibeguard-rules.md`，其中以表格行重复规则正文）。
- `eval/datasets/v1.jsonl` 共 40 条样本，`rule == "NONE"` 仅 4 条，单个规则最多 4 条。
- 整个流程是**单次运行**：只有"带全部规则跑一遍"，没有"不带候选规则跑一遍"
  作为对照，因此无法归因任何行为差异。

## 目标

- 提供配对（with / without 候选规则）运行能力，复用既有的 model-backed 路径。
- 规则通过门需要**同时**满足两条证据轴：
  - **目标场景改善**：这条规则存在的理由所对应的行为，确实发生了改变。
  - **非目标不回归**：一组与该规则无关的固定任务没有变差。目标轴复用现有
    structured-JSON grader；非目标轴由盲化、换序复核的 pairwise judge 比较输出质量。
- 产出可复现的差异指标，并作为规则 PR 模板中的必需证据。

## 非目标

- 不替换确定性行为门。hook 强制的规则继续由 `eval/behavior/` 覆盖。
- 不做上线后的持续追踪。持续精度归 guard-precision-tracker（GH-675）。
- 不在本 issue 中新增或修改任何实际规则。
- 不把配对评测接入默认 CI 阻断路径：它需要真实模型调用，成本与不确定性都不适合
  每次 push 运行。它是规则 PR 的按需门。

## Behavior Invariants

1. B-001: 必须能在一次调用中，对每条证据轴各执行一次 with-candidate 与一次
   without-candidate 运行（两轴共四次），且同一轴内的两次运行除候选规则文本外的所有
   输入（模型、样本集、其余规则）完全一致。
2. B-002: 每次运行的输入身份必须可审计：分别记录 `rule_digest`、`dataset_digest`、
   `sample_set_digest` 与解析后的模型 ID。**同一轴内**的 with/without 之间，除
   `rule_digest` 外必须全部相等；模型 ID 四次运行必须一致。不相等时以错误终止而不是
   继续比较。两轴之间的数据集摘要本就不同，不参与该断言。报告中的 commit SHA 必须在
   首个模型调用前固定，运行中 HEAD 变化不得改写证据归属；无法解析 commit 时必须在
   创建模型客户端前终止，不得产生无法绑定版本的付费证据。真实运行还必须在导入仓库内
   评估器模块前固定 commit，并在调用模型前再次确认规则树、core、两个数据集、阈值、
   模型基线与由 import 关系推导的评估器本地依赖闭包都已由该 commit 跟踪且无未提交
   变化，并逐文件确认实际 worktree blob 等于该 commit blob；Git 状态隐藏标记不得绕过
   校验。仓外、untracked 或 dirty 输入只能 dry-run，不得冒充 PR 证据。
3. B-003: 候选规则的排除必须覆盖**全部**注入来源，并同时满足四条断言：
   (a) **逐文件差分**：临时规则树与真实树相比只允许一个文件不同，且该文件的差异**恰为**
   候选小节；core 文件的差异恰为该 ID 的表格行；其余文件逐字节相同。比较必须在文件层
   进行，不得在拼装后的整段文本上重放剔除——`load_rules` 用 `# {stem}` 头拼接文件，
   在拼装文本上按 `^## ` 分界会越过文件边界，对当前 127 条定义中位于文件末节的 18 条
   规则产生假失败。文件内边界必须是下一条 canonical `^## <RULE-ID>:` 定义，不能是任意
   Markdown 二级标题；W-11 正文中的 fenced `## Facts` / `## Inferences` 属于候选正文。
   (b) **在场**：候选定义必须真的存在。找不到时以"候选规则不存在"终止 —— 否则剔除是
   no-op，两个完全相同的运行会冒充合法对照，把"ID 写错"误报成"规则无效果"。
   (c) **定义计数**：with 与 without 的 `^## <ID>:` 定义数之差必须**恰为 1**，且被删 span
   内除首个候选标题外不得再出现 canonical 规则定义。普通 `##` 标题可以是规则正文。
   这条不依赖剔除逻辑自身，是抓"删多了"的非同源断言。
   删多了是唯一会制造**假 pass** 的失效模式：其余断言两侧共用同一剔除逻辑，一起删多了
   仍然全部通过，而 without 少掉的无关规则会系统性放大目标轴 delta。
   (d) **定义位点**：候选的定义位点不得出现在 without 文本中。这条抓"删漏了"。
   若匿名 compact L1-L7 项仍承载候选或 placebo 的等价语义，则不能用仅删除原生定义来
   声称有效对照；v1 对已知等价映射直接报 unsupported，且必须发生在任何付费调用之前。
4. B-012: 其它规则正文对候选 ID 的**交叉引用**是无法消除的已知残留——删除它们会违反
   B-001 的"其余规则完全一致"。因此断言范围限定在候选自身的定义位点，交叉引用必须在
   报告中逐条列出（`文件:行号`）；数量超过 `max_cross_refs` 时结果为 `inconclusive`。
   只写进 caveat 而不影响判定等于"记录即免责"，会把"对照被严重污染"与"对照干净"输出成
   同一个 `pass`。当前全仓 127 条规则中有 30 条被其它规则文件引用，其中包括本 issue
   用来论证动机的 U-32；U-32 当前有 13 处候选小节外引用，超过默认阈值 4，因此应明确
   得到 `inconclusive`，不得通过漏算引用来压到阈值内。
5. B-004: 必须区分两组样本：**目标样本**（`rule` 字段**精确等于**候选规则 ID）与
   **非目标样本**（一组与候选规则无关的固定集合）。每条非目标样本声明
   `excluded_rules`；候选命中该列表时必须从该次样本集排除，避免把候选的目标行为误算成
   副作用。排除项必须在所选规则树的 canonical inventory 中存在，拼错或未知 ID 必须在
   模型调用前报错。两组都为空时以错误终止。前缀匹配或混入通用样本都会污染目标轴。
6. B-005: 判定必须同时要求两条轴通过；任一条不通过即整体不通过。单轴通过不得被
   报告为"通过"。
7. B-006: 必须区分"没有回归"与"样本量不足以判断"。**任一轴**样本量低于配置的最小值
   时，结果为 `inconclusive`，不得报告为 `pass`；两个最小样本阈值必须为正整数，空轴
   即使绕过配置加载也必须 fail closed 为 `inconclusive`。
8. B-007: 任何跳过的样本（API 失败、解析失败、producer 空白响应）必须计入并可见；
   空白响应不得交给 judge 伪装成可比较输出；被跳过的样本不得
   静默地从分母中消失。跳过率超过阈值、或 with 与 without 的跳过率之差超过阈值时，
   结果为 `inconclusive` —— 跳过率偏差会直接主导两轴的差值。运行中收到
   `KeyboardInterrupt` 时必须停止发起新模型请求，把当前及后续未完成样本记为 skipped，
   保留此前已付费结果并写出带中断阶段的 partial report，非零退出。报告目录必须在首个
   模型调用前创建并验证可写；目标不可写时不得开始付费运行。
9. B-008: 必须提供离线 dry-run 路径：不调用模型，输出四次运行的输入身份、剔除断言
   结果与样本划分，供确定性测试与人工核对使用。**dry-run 不产出判定**，因此不受 B-010
   与 B-011 约束，正常完成时退出 0。否则未标定阶段的 dry-run 会恒定非零退出，它的
   确定性测试永远无法通过。
10. B-009: 规则 PR 模板必须要求附上配对评测结果，或显式声明豁免理由；豁免仅适用于
    非 prompt 注入类改动，且需要维护者批准记录。无约束的豁免等于没有门。在
    `calibrated: false` 阶段，可接受的证据形态是 **inconclusive 报告加两轴 delta 数值
    与样本量**，而不是 `pass` —— 否则 B-010 会让任何 prompt 规则 PR 既拿不到可用证据
    也拿不到豁免。
11. B-010: 阈值未标定时，整体判定强制为 `inconclusive`，永不输出 `pass`。仅打印警告
    不足以阻止下游把未标定的门当作已标定的门引用。
12. B-011: **产出判定的真实运行**中，`inconclusive` 与不通过一样以非零退出码结束。
    退出码为 0 的 `inconclusive` 等于门不存在。dry-run 不产出判定，不适用本条。

13. B-013: 报告必须输出 with/without 的**规则文本字符数与差值**，与两轴 delta 并列。
    without 少了一整节，上下文总长度与其后所有内容的位置都变了，因此目标轴 delta 里混着
    两个因素：候选规则的语义作用，以及"少了 N 个 token"本身带来的一般性行为变化。这对
    本门尤其致命——issue 要测的正是注意力挤占，**长度本身就是被研究的自变量**，用"删掉
    它再比一次"去测"它是否挤占注意力"，自变量与混杂因子是同一个东西。四条剔除断言全在
    文本正确性层，对此原理上无感：它们能证明"只删了候选"，证明不了"delta 归因于候选的
    语义"。
14. B-014: 标定实验必须包含**安慰剂对照**：删除一条与目标样本完全无关、不同于候选且
    长度相近的规则，跑同一份目标数据集，期望 `delta ≈ 0`。v1 以
    `max_placebo_length_ratio: 0.25` 限定相对候选长度的最大差异；长度必须按两个来源均
    剔除后的完整 `load_rules` prompt 字符差比较，不能只比较原生小节。超出即拒绝运行；
    placebo 还必须命中维护者明确审核为语义无关的 pair 映射，并通过匿名 compact 等价
    语义检查；其交叉引用残留同样受 `max_cross_refs` 约束，任一不满足都必须在付费调用前
    拒绝。若 placebo 的 delta 与真候选同量级，说明本门测到的是上下文长度效应而非规则语义，
    `min_target_delta` 必须定在 placebo delta 的分布之上，否则整个门在测噪声。
15. B-015: 目标轴必须复用现有 structured-JSON grader；非目标轴必须用不知道哪份输出来自
    with/without 的 pairwise judge，且每个样本将 A/B 位置互换后再判一次。两次判定映射回
    with/without 后不一致时，该样本标记为 judge conflict，非目标轴为 `inconclusive`，
    不得择一或平均后继续。报告必须记录 producer model ID、judge model ID、judge prompt
    digest、两次原始判定及映射后的 `with_win` / `without_win` / `tie` / `conflict`；
    judge 返回 malformed JSON 时也必须先保存付费原文，再把该样本记为 skipped。

## 验收标准

- [ ] 存在配对运行入口，接受候选规则 ID 与非目标样本集。
- [ ] 候选规则从两个注入来源同时剔除，且由逐文件差分/在场/计数/定义位点四条断言证明；
      整文件删除、no-op 剔除、贪婪多删一节均必须被拒。
- [ ] 匿名 compact 项仍保留等价语义的候选在模型调用前被明确拒绝，不产出伪 with/without
      证据。
- [ ] 输入身份不一致时以非零退出码终止并说明哪一项不一致。
- [ ] 目标轴与非目标轴分别报告，整体判定为两者的合取。
- [ ] 非目标轴使用盲化、换序复核的 pairwise judge；位置偏差冲突 fail closed 为
      `inconclusive`，且 judge 身份与原始判定可审计。
- [ ] 任一轴样本量不足、跳过率超阈值、或阈值未标定时报告 `inconclusive`。
- [ ] Ctrl-C 停止后续模型调用、保留已完成结果并写出 partial inconclusive 报告。
- [ ] 导入仓库内评估器模块前固定 commit SHA，并在首个模型调用前确认规则、数据、阈值、
      模型基线及评估器本地依赖闭包均由该提交跟踪且干净，同时预留可写报告路径；commit
      无法解析、输入 dirty/untracked/仓外或目标不可写时零模型调用失败。
- [ ] 产出判定的真实运行中，`inconclusive` 与不通过均以非零退出码结束（dry-run 不产出
      判定，正常完成退出 0，见 B-008）。
- [ ] dry-run 路径不需要 API 密钥即可运行，并被确定性测试覆盖。
- [ ] 规则 PR 模板包含配对评测证据要求，且豁免受限。

## 边界情况清单

| 类别 | 判定（covered: B-xxx / N/A + 原因） |
| --- | --- |
| 空/缺失输入 | covered: B-004；两组样本都为空时终止 |
| 错误与失败路径 | covered: B-002, B-007, B-015；输入漂移终止，跳过样本可见，judge 换序冲突不降级为有效分数 |
| 授权/权限 | covered: B-008；无密钥时 dry-run 仍可用，真实运行明确报缺密钥 |
| 并发/竞态 | N/A — 四次运行串行，无共享可写状态 |
| 重试/幂等 | covered: B-002；同一输入身份可复现，摘要用于比对 |
| 非法状态转换 | covered: B-005；单轴通过不得升格为整体通过 |
| 兼容/迁移 | covered: B-001；共享 `run_eval` 的下层组件，不改单次运行语义 |
| 降级/回退 | covered: B-006, B-010, B-011；样本不足与未标定都是 `inconclusive` 而非 `pass`，且非零退出 |
| 证据与审计完整性 | covered: B-002, B-003, B-012, B-015；四条断言同时封住删漏与删多两个方向，交叉引用残留与 judge 原始判定均可审计 |
| 取消/中断 | covered: B-007；中断导致的未完成样本按跳过计入 |

## 前置决策

初版把三个问题都推给维护者。核对代码并取得维护者裁定后，三项均已确定：

- **非目标任务集从哪来 → 已定：必须新建。** `eval/datasets/v1.jsonl` 只有 4 条
  `NONE` 样本，而非目标轴需要的下限是 30。从 v1 划分在算术上不成立。
- **样本量标定 → 已定：先落地方向性门。** `calibrated: false` 强制 `inconclusive`
  之后，未标定的门不会产生误导性的 `pass`，标定实验可以独立进行。
- **打分方式 → 已定：混合打分。** 目标轴复用 structured-JSON grader；非目标轴使用
  盲化、换序复核的 pairwise judge。`eval/dataset.py:105-118` 的现有 schema 只表达
  detection / false-positive 任务，不能冒充普通任务质量度量；新 non-target 数据集必须
  携带供 judge 使用的任务与质量 rubric。

## 发布说明

配对评测是按需运行的规则 PR 门，不进默认 CI。它需要 Anthropic API 密钥；
dry-run 路径不需要。
